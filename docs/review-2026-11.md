# Adversarial review, November 2026

Reviewed against bee v2.8.3 (mainnet since 2026-10-15), the
swap-swear-and-swindle contracts and storage-incentives' PostageStamp.
WASM-only code was out of scope.

Fixes landed as separate PRs, one per area. The transport PR
(`fix/session-lifetime`) carries session lifetime, retrieval accounting,
background settling and session retirement together. It and the SWAP PR
(`fix/swap-cheque-rates`) add helpers at the same spot in `transport.rs`, so
whichever merges second needs a trivial rebase.

## Measured on mainnet

- Daemon session retention, pool target 64, 4 min per arm, interleaved
  main/fix/main/fix, no uploads: the fix held 64/64 sessions on a single dial
  wave; `main` averaged ~55 live and dialed ~700 sessions per arm.
- A 15-minute soak of the integration build held 64/64 sessions at every
  15 s sample, across three of bee's 5-minute kademlia prune ticks, on one
  dial wave of 64 and no replacements.
- A final 60 s smoke of the integration tip: 64/64 live, 175 hive streams
  answered with none failed or oversized, and a missing reference failing in
  26 s at the default of 32 retries.
- Fetch of the 40 MB MEDIUM object from bee#5541, which has since expired
  (the public gateway returns 404 for it): at the old unlimited retry
  default both builds stalled at the same node, more data chunks gone than
  its parity covers. Up to that point the integration build requested 3690
  chunks in 283 s against 740 s on `main` (one run each).
- Same object at `--max-retries 32`, two runs each: `main` was still
  retrying when killed at 480 s; the integration build failed with
  `Unrecoverable { have: 77, need: 84 }` in 24-25 s.
- A random (absent) reference at `--max-retries 20`: `main` was still
  retrying when killed at 300 s; the integration build failed with "all
  peers failed (20/20 attempted) ... storage: not found" in 17 s.
- One-shot uploads, 20 MiB of fresh random data, `--concurrency 128`,
  three interleaved pairs from a residential connection: 282, 265 and
  257 KiB/s on `main` against 1198, 782 and 1055 KiB/s with the fixes.
  Sessions retired per upload fell from 140-155 to 1-2.
- The stamp-slot bug, observed: three `main` uploads to one batch, then the
  public gateway. The first two returned HTTP 500; only the newest came
  back. All three uploads with the fixes, to another batch, came back
  byte-identical.
- Daemon mode on `main`, pool 128, three 20 MiB uploads: 282 KiB/s, then
  20 KiB/s, then a stall on the last chunk after 33 minutes, with 449
  session deaths. The same run with the fixes was not done.

## Open

### Transport and protocols
- medium: Shallow-receipt check trusts the storer's self-reported radius;
  bee also compares against its own radius (`pushsync.go` checkReceipt).
- medium: A second connection to a still-connected peer is treated by bee as
  a duplicate; no pricing announcement comes, so the prewarm dial times out.
- low: StreamControl and pushsync frame errors mark the whole session dead.
- low: Opening a stream on a closed connection makes the stream pool redial
  outside the handshake (settles now check first; other paths don't).
- low: The cached handshake timestamp goes stale if another process with the
  same key and nonce handshakes first (`ErrTimestampStale`).
- low: Pseudosettle acks aren't checked for accepted > requested or clock
  skew; over-long big-endian fields are truncated rather than rejected.
- low: Hive self-announce runs inside the 3 s dial budget.

### Upload path
- medium-high: The relay scheduler scans every chunk ever admitted on each
  event (O(N²) over an upload).
- medium: The relay driver spins when a deadline has passed but no hedge is
  possible; a re-sent chunk's bookkeeping can double count or end early.
- medium: Prewarm results are ignored in the upload tail and the in-flight
  flag can stick across daemon requests.
- medium: When a session dies, every push on it dials a replacement.
- medium: A parked peer is pruned and redialed within seconds.
- medium: A shallow-only chunk walks the whole pool serially, up to 60 times.
- medium: Relay acks are trusted without the storer receipt.
- medium: Large uploads hold ~2-3 copies of the data; with `--listen` the
  daemon chunk cache is unbounded.
- low: `batch_max: 0` from a relay; driver early exit on a timing race;
  in-flight cap undercounts; one-shot pool floor not applied; latency sort
  discards address spread; receipt PO metric measures the first hop; double
  signature recovery per receipt; on-chain bucket depth ignored; relay POST
  tasks not cancelled; POST buffer under-sized.
- upstream (nectar-mantaray): the encoder refuses any node over 4096 bytes,
  so uploading a directory level with more than a few dozen distinct name
  starts fails. Bee splits such nodes.

### Fetch path
- medium: Join amplification: identical refs and zero-span children let a
  few chunks expand to 8 GiB or ~10^8 visits.
- medium: Only v1 feed payloads are understood.
- medium: The candidate list is rebuilt and sorted per chunk.
- medium: The joiner finishes each subtree before starting the next.
- medium: The per-fetch cache keeps every chunk (~2× file size in memory).
- low: RS-reconstructed chunks aren't checked against their reference; SOCs
  are accepted anywhere in a tree; no in-flight dedup; `--path /` and
  directory index handling; the retrieval session cache only shrinks on
  `ConnectionClosed`.

### Relay and billing
- medium: Relays sharing a beneficiary across separate ledgers double-credit.
- medium: `/v1/challenge` is rate-limited per TCP peer IP, which is the proxy.
- medium: Client-chosen dust floor on `/v1/pay`; synchronous full-ledger
  rewrite under a std mutex per payment.
- medium: The client's balance check double-counts cashed amounts.
- medium: `max_outstanding_plur` is whatever the relay signs; the client
  has no ceiling on it.
- low-medium: RPC errors (with the RPC URL and any key in it) are returned to
  callers.
- low: Ledger durability and file mode; non-402 refusals billed client-side;
  `/v1/meter` open under `--meter`; unthrottled CPU endpoints; cashout
  checks; `/v1/tcpcheck` is an SSRF when `--probe` is on.

### Daemon, peers, CLI
- medium: Reachability ranking in the daemon is frozen at startup.
- medium: Socket permissions follow the umask; the client sends the key to
  whatever listens at the path.
- medium: `cheques.json` has no cross-process lock or fsync.
- medium: Hive gossip is stored without verifying signatures or capping
  entries per message.
- medium: `auto_iterate_anchors` runs a multi-second keccak loop on the async
  runtime every 180 s.
- low-medium: Progress writes block the upload future; `Listed` replies over
  1 MiB fail; the IPC nonce doesn't change the daemon's overlay.
- low: Status responder's `BatchCommitment` never matches the network, so
  salud marks us unhealthy anyway; keys only via argv; inbound has no
  connection limits; socket unlink without checks; listener bind failure is
  not fatal; no SIGTERM handling; dnsaddr aborts on one failed child;
  unroutable-IP filter gaps; collections skip the warm pool.

### On-chain
- low-medium: `bridge --to both` spends the top-up on top of `--amount`.
- low: Cheques keyed by peer overlay rather than beneficiary; chequebook
  deploy simulated from `0x0`; no fee ceilings; u64
  conversions that panic on hostile RPC output; `chequebook fund` skips the
  factory check; `--duration` buffer too thin.
